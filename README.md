# Gestione Siti — Multi-site CMS

Multi-tenant CMS for managing multiple websites from a single admin panel, designed to be driven both by human users and by an AI agent via a dedicated API.

## Main features

- **Multi-site / multi-domain**: multiple independent sites, each with multiple associated domains (`site_domains`).
- **Page editor** with automatic versioning, preview, scheduled publishing, redirects, per-page SEO.
- **Reusable snippets and templates** across pages, with `{{snippet:...}}` placeholders and `{{var:...}}` site variables.
- **Media library**: upload, import from URL (including Google Drive links), automatic video compression, LLM-generated alt text, audio/video transcription.
- **Public forms** with a form builder (text/email/phone/long text/dropdown/single-choice/checkbox questions), submission collection and CSV export from the admin panel.
- **Static export**: every published page is exported as static HTML, served by a separate Caddy as a fallback when the Express app is under maintenance (zero downtime).
- **Dedicated AI agent API** (`/api/agent/...`, documented in [`locales/en/AGENT.md`](locales/en/AGENT.md) / [`locales/it/AGENT.md`](locales/it/AGENT.md)): lets an AI agent (Claude Code, OpenCode, etc.) read and edit pages/snippets/media autonomously, with "bulk" endpoints designed to reduce the number of calls. `GET /api/agent/guide` serves the version in the installation's language (`DEFAULT_LANG`).
- **MCP server** (`/api/mcp`, documented in [`locales/en/MCP.md`](locales/en/MCP.md) / [`locales/it/MCP.md`](locales/it/MCP.md)): the same functionality as the agent API exposed as MCP tools for clients like Claude Desktop, generated by introspecting the REST routes — always automatically in sync.
- **Configurable branding and theme** per-installation (`.env`) and per-site (`site_variables`: colors, logo, footer).
- **i18n**: admin interface available in Italian/English (string migration in progress). Agent documentation (`AGENT.md`/`MCP.md`), MCP tools, API messages, and transactional emails are bilingual EN/IT with English as the base language (see `locales/`).
- **RBAC**: `superadmin` / `admin` / `collaboratore` roles with granular per-resource permissions (`src/constants/permissions.js`).
- **CRM-lite**: contacts derived from form submissions (tags, status, notes), cross-form search, optional per-site modules — fixed-stage sales pipeline and call management (log + public self-booking).
- **Long-lived API tokens** (`/admin/api-tokens`) for non-interactive integrations (n8n, other automations), alongside interactive OTP login.
- **Tracking & Analytics** (`/admin/settings/tracking`): Google Analytics 4, Google Tag Manager, Meta Pixel + server-side Conversions API, Microsoft Clarity, Search Console verification — with an auto-generated GDPR consent banner (Google Consent Mode v2) as soon as anything is configured.
- **AI-generated content disclosure** (AI Act Article 50, optional): configurable footer notice for sites publishing AI content without human editorial review on matters of public interest.

## CRM, pipeline and call management

Beyond site management, the CMS ships a **full CRM** that can be enabled per site via optional modules (`site_modules`, toggle in `admin/sites/:id/edit`). There are two modules: **Sales pipeline** (`sales_pipeline`) and **Calls** (`call_scheduling`). All CRM data (contacts, opportunities, quotes, calls) is always tied to a site (`site_id`) and governed by granular RBAC permissions.

### Contacts (CRM-lite)

- **Origin**: contacts are derived automatically from public form submissions (tags, status, notes), with cross-form search.
- **Contact record** (`/admin/contacts/:email`): status, tags, notes, activity history, columns linked to the pipeline/calls module when enabled.
- **Operations**: add/remove notes, edit fields, export, delete.

### Sales pipeline (module `sales_pipeline`)

- **Purpose**: track the commercial progress of contacts across fixed stages.
- **Fixed stages** (vocabulary in `src/constants/pipeline.js`): `lead` → `contattato` → `chiamata_fissata` → `proposta_inviata` → `vinto` / `perso`. A contact whose status is not one of these keys (empty, or pre-existing free text) appears in the "To assign" column.
- **Kanban board** view (`/admin/pipeline`) to move contacts between stages, with the associated estimated deal value.
- **Stage change with validation**: unknown stages are rejected.

### Opportunities and quotes

- **Opportunities/deals** (`/admin/opportunities`, board `/admin/opportunities/board`, drag & drop kanban): each opportunity is tied to a contact and to a pipeline with **customizable stages** (`pipelines`, `db/043`); it carries a title, amount, probability (0-100), status (`open`/`won`/`lost`), expected close date and notes.
- **Notes & history** on each opportunity (dedicated API endpoints), stage movement via API (for drag & drop and automations).
- **Quotes** (`/admin/quotes`): documents linked to an opportunity and a contact, with line items (`items` JSONB: description, quantity, price), a progressive number, and a status that progresses `draft` → `sent` → `viewed` → `signed`.
- **Public token**: each quote has a unique token for the customer-facing link (`pref_token` pattern), so the customer can view/sign it without credentials.

### Call management (module `call_scheduling`)

- **Call log**: schedule and record calls from the contact record, with outcome.
- **Calendars** (`/admin/calls/calendars`): create, edit, delete availability calendars for calls.
- **Weekly availability** (`/admin/calls/availability`): recurring weekly slots.
- **Public self-booking** (`/book/:siteId/:calendarSlug`): the contact can book a slot autonomously; booking cancellation via token.
- **Protection**: rate limiting on public booking endpoints.

### Call recordings

- **Upload** (`/admin/call-recordings`): upload audio files, search and manage.
- **Processing** (`process`): automatic extraction of information from the recording (via LLM).
- **Review** single or bulk (`review`, `bulk-review`): review and validate the extracted transcriptions.
- **Settler** (`/admin/call-recordings/settler`): weekly settler commission report, with history for the last weeks.
- **Protection**: rate limiting on processing.

### Other CRM tools (`/admin/crm`)

- **CRM dashboard** with activity summary.
- **Segments** (`segments`): define sets of contacts.
- **Workflows** (`workflows`): automations/rules.
- **Tasks** (`tasks`): to-do management with status.
- **Funnel** (`funnel`): conversion flow analysis view.
- **Conversations** (`conversations`): thread management with messages and status.

### Newsletter and social

- **Newsletter** (`/admin/newsletter`): subscriber management (with export), campaigns, email templates, SMTP settings with **connection test**.
- **Social poster** (`/admin/social`): **currently a stub** (only checks the token is present, does not actually publish).

## Stack

Node.js (Express, ESM) + EJS + PostgreSQL, containerized with Docker. Authentication via magic link + email OTP (no passwords).

## Deployment architecture

```
                      ┌──────────────────────────────────┐
                      │        proxyssl (Caddy)           │
                      │  (ports 80/443, SSL, routing)      │
                      └──────┬───────────────────────────┘
                             │
                     requested domain
                             │
                      ┌──────▼───────────────────────────┐
                      │    caddy-gestito (Caddy:8080)     │
                      │  serves media/static from disk,    │
                      │  proxies to the CMS if needed      │
                      └──────┬───────────────────────────┘
                             │
                ┌────────────┼────────────┐
                │            │            │
          static files     media          API
     (./static/{host})  (./media)   reverse_proxy
                                          │
                                   ┌──────▼──────┐
                                   │ CMS Express │
                                   │  (port 3000) │
                                   └──────┬──────┘
                                          │
                                   ┌──────▼──────┐
                                   │  Postgres   │
                                   └─────────────┘
```

### Components

1. **CMS** (`docker compose up -d`, project root) — `gestione-siti` service (Express+EJS) + `db` (Postgres 16).
2. **Managed Caddy** (`docker compose -f caddy-gestito/docker-compose.yml up -d`) — serves `media/`/`static/` from disk and reverse-proxies to the CMS; this is the stack that stays up even if the CMS is down.
3. **SSL Proxy** (`proxyssl/`, separate infrastructure) — terminates TLS on ports 80/443 and forwards to the managed Caddy.

### Docker networks

| Name | Type | Purpose |
|---|---|---|
| `edge_net` | external | Connection between proxyssl and internal services |
| `gestione_siti` | external | Connection between the CMS and caddy-gestito |
| `internal` | bridge | Connection between the CMS and db (not externally accessible) |

Create the external networks before starting:
```bash
docker network create edge_net
docker network create gestione_siti
```

## Quickstart (Docker)

```bash
# 1. Clone the project and create the networks (if they don't exist)
docker network create edge_net
docker network create gestione_siti

# 2. Copy .env.example → .env and customize it (required: DB_PASSWORD, JWT_SECRET)
cp .env.example .env

# 3. Start the CMS (also runs DB migrations on every boot, see db/migrate.js)
docker compose up -d

# 4. Populate the static directory
bash caddy-gestito/init-static.sh

# 5. Start the managed Caddy
docker compose -f caddy-gestito/docker-compose.yml up -d

# 6. Run the first static export of all sites
docker compose exec gestione-siti node scripts/static-export-all.js
```

### First superadmin (bootstrap)

The CMS has no self-registration: every user is created by an existing
superadmin (via `/admin/users`), and migrations only seed the default site.
For a fresh install, create the first superadmin with the idempotent script
(no auth needed — it only inserts when the email doesn't exist yet):

```bash
# from the host, with the DB up:
SUPERADMIN_EMAIL=admin@esempio.it node scripts/create-superadmin.js
# or as argument:
node scripts/create-superadmin.js admin@esempio.it
```

Then open `/admin`, request a magic link (OTP via email) and log in. If
`SMTP_*` is not configured, the email is not actually delivered (the app
falls back to `jsonTransport`); you can create the OTP flow manually or
configure SMTP first.

Caddy configuration for new sites: the CMS mounts `./caddy-config` and dynamically generates config files for each site from the admin interface. The managed Caddy doesn't mount this directory by default — the static configuration (media/static/proxy) is enough for basic operation.

## Environment variables

See [`.env.example`](.env.example) for the full list with defaults. The main ones:

| Variable | Required | Notes |
|---|---|---|
| `DATABASE_URL` | Yes | Postgres connection string |
| `DB_PASSWORD` | Yes | Postgres password (also used by `docker-compose.yml`) |
| `JWT_SECRET` | Yes | Key for JWT tokens (`openssl rand -hex 64`) |
| `SMTP_HOST`/`SMTP_USER`/`SMTP_PASS`/`EMAIL_FROM` | No | Needed to send magic links via email |
| `MAGIC_LINK_BASE_URL` | No | Base URL used in email access links |
| `APP_NAME`/`APP_TAGLINE`/`APP_LOGO_TEXT`/`ADMIN_TITLE`/`SITE_DEFAULT_BRAND`/`DEFAULT_LANG` | No | Installation branding, neutral defaults |
| `OPENAI_API_KEY` | No | Used for audio/video transcription (Whisper) |
| `LLM_BASE_URL`/`LLM_MODEL`/`LLM_API_KEY` | No | LLM provider for text rewriting and image alt text (default: OpenAI, falls back to `OPENAI_API_KEY`) |
| `CLOUDFLARE_ZONE_ID`/`CLOUDFLARE_API_TOKEN` | No | Cloudflare cache purge on deploy |
| `DEPLOY_WEBHOOK_URL` | No | Webhook called on every deploy |
| `TWITTER_BEARER_TOKEN`/`LINKEDIN_ACCESS_TOKEN`/`FACEBOOK_PAGE_TOKEN` | No | Social poster (currently a **stub**: only checks that the token is configured, doesn't actually publish) |

## Project structure

```
src/
  index.js            Entry point, Express setup, global middleware, route mounting
  config.js            All configuration from env, with defaults
  constants/            Shared constants (RBAC permissions)
  middleware/           auth, CSRF, i18n, resolve-site, authorize, ...
  routes/               One file per functional area (pages, media, agent, settings, ...)
  services/              Business logic and integrations (static export, deploy, email, LLM, ...)
db/                    Numbered SQL migrations, run in order by db/migrate.js
views/                 EJS templates (views/admin/* for the panel, views/auth/* for login)
locales/                Translation files (it.json, en.json) and multilingual agent docs (locales/en|it/AGENT.md, MCP.md)
scripts/                Operational scripts (container startup, CLI static export, agent login)
caddy-config/            Dynamically generated per-site Caddy config
caddy-gestito/           Separate Docker stack for the static fallback
```

## Local development

```bash
npm install
npm run dev      # node --watch src/index.js
npm run migrate  # applies DB migrations not yet run
```

Requires a reachable Postgres connection (`DATABASE_URL`) and `ffmpeg`/`gdown` for video compression and Google Drive import.

## Tests

```bash
npm test   # runs migrations against the test DB, then node --test
```

Requires a dedicated test Postgres (never production — tests write data),
e.g. a disposable container:

```bash
docker run -d -e POSTGRES_PASSWORD=test -e POSTGRES_DB=testdb -p 15999:5432 postgres:16-alpine
DATABASE_URL=postgres://postgres:test@localhost:15999/testdb JWT_SECRET=any-value npm test
```

No external framework: built-in `node:test`. Coverage is not exhaustive —
it focuses on cross-module handoffs (form → CRM → newsletter) and known
security regressions (`test/calls.test.js` includes the case that
uncovered the forged client-side `duration_minutes` vulnerability).
